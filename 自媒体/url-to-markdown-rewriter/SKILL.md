# URL to Markdown 洗稿整理

## 核心原则

先追溯来源，再重构表达。这里的“洗稿”只能理解为合法的资料消化、结构重组和原创改写；不能搬运、规避版权、伪装原创出处或大段复写原文。

## 使用时机

- 用户给 URL，希望转成 Markdown。
- 用户要把参考文章拆成可复用素材、观点和发布草稿。
- 用户要基于外部内容写公众号、小红书、微博或内部笔记。
- 用户要求“文章转 Markdown”“洗稿格式”“改写成自己的文章结构”。

## 工作步骤

1. 读取 URL 或用户粘贴的原文；无法访问时明确说明缺口，不编造。
2. 记录来源：标题、作者/机构、发布时间、URL、访问日期。
3. 区分事实、观点、案例、数据和可借鉴表达。
4. 输出 Markdown 资料卡，而不是原文搬运。
5. 若要生成新稿，重新组织主题、顺序、例子和语言；只保留必要短引用。
6. 标出需要二次核验的数据、政策、价格、时间、人物身份和平台规则。

## 输出模板

```md
# 标题

来源：
访问日期：
用途：

## 原文要点

- 

## 可复用素材

- 事实：
- 案例：
- 观点：
- 金句/短引用：

## 重构后的文章骨架

1. 
2. 
3. 

## 可发布草稿

...

## 需核验

- 
```

## 边界

- 不输出完整受版权保护原文。
- 不保留长段原文句式。
- 不删除必要出处。
- 不把未经证实的信息写成事实。
- 涉及医疗、法律、金融、政策或平台规则时，必须核验最新来源。
