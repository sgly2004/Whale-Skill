# 设计文档模板

标准范例：`docs/Engineering/backend/{中文模块名}.md`  
可读性规范：[文档可读性规范.md](../../../docs/Engineering/文档可读性规范.md)（**必守**：无文首术语表；关键词首次出现标「类别 + 含义」，类别见规范 §一）

---

## 文件头

```markdown
# {module} 模块数据流梳理

> 产品域：… · 契约：…

**相关代码**
- `{module_dir}/` — 模块根目录
- …

## 一、功能入口

**用户操作入口**
- {用户主动完成的完整意图}

**管理员操作入口**（仅当存在时写此节）
- {管理员在后台的完整操作}

**业务流程入口（由其他模块触发，无用户直接操作）**（仅当存在时写此节）
- {如：支付成功后授权权限}

以下不算入口，是支撑性能力：{列举子步骤接口、列表查询、鉴权依赖等}。
```

**入口章节**：某类入口不存在则**整段省略**，不写「无」占位。

**入口判定口诀**

| 算入口 | 不算入口 |
|--------|----------|
| 用户/管理员主动完成的业务意图 | 某流程内的子步骤（发短信验证码） |
| 其他模块/定时任务触发的完整业务流程 | 获取 xx 列表、获取详情 |
| | 鉴权、门控、刷新 token 等基础设施 |
| | 单独的路由路径名称 |

## 二、数据流详解

每条数据流一个 `###` 小节，编号连续。

```markdown
## 二、数据流详解

### 数据流 1：{名称}

**触发**：{从用户操作或业务流程描述，不写 POST /xxx}

{段落 1：前端/调用方做什么}

{段落 2：鉴权要求}

{段落 3：后端处理逻辑与业务规则——数据如何变化、为何这样设计}

{段落 N：返回什么、推送什么}

**落库产物**：`table_a` 新行（字段含义见 **五、数据表**）；`table_b`（条件性写入，定义见 xx 模块）。

{可选 **中间产物**：订单 status=created，等待支付回调}

{可选 **补充——xxx**：重复路由、dev 通道、与另一路径的区别}
```

### 写法要点

**好的描述**（连贯叙述）：

> 用户打开小程序时，小程序侧调用微信 `wx.login()` 得到一个临时 code。前端把 code 发给后端登录接口。后端用 AppID 和 AppSecret 向微信换取 openid 和 session_key，按 unionid 优先查找用户，找不到则创建新用户，最后签发 JWT 返回。

**坏的描述**（禁止）：

> `wx.login()` → `POST /auth/login` → `exchange_code()` → `find_user()` → `create_jwt()`

> `INSERT INTO user (openid, ...) VALUES (...)`

> `UserCreateSchema` 包含 `openid: str, unionid: Optional[str]`

## 三、支撑性能力说明

不属于独立数据流，但是模块提供的基础能力。

```markdown
## 三、支撑性能力说明

**JWT 鉴权与自动续期**：{何时介入、检查什么、失败如何处理}

**{门控/查询能力名}**：{前端在什么场景调用、返回什么决策信息}
```

## 四、冗余与待清理功能

```markdown
## 四、冗余与待清理功能

- `{路由或功能}`：{与谁重复 / 为何废弃 / 前端是否仍调用}
- `todo：{未完成项}`：{当前状态与计划}
```

提问式待确认项也在此或阶段一汇报中列出，例如：

- `dev-login` 与原生 `wx.login` 前端该走哪条？
- `/login` 与 `/login/wechat-miniprogram` 区别？能否删旧路由？
- `/bind-phone` 与 `/bind-phone/sms` 各自用途？

## 五、数据表

> Schema 来源：`backend/src/{module}/models.py`（或实际路径）  
> 写法遵循 [文档可读性规范.md](../../../docs/Engineering/文档可读性规范.md)

本模块**拥有**的物理表：每张表先写 **这张表记什么**，再写字段表 + 行生命周期。

```markdown
### 表：`{table_name}`（{中文短名}）

**这张表记什么**：{1～3 句：一行代表什么、和哪张表分工、回答什么业务问题}

| id | org_id | status | created_at |
| --- | --- | --- | --- |
| 主键 | 组织 ID（{在业务里表示…}） | 状态（{各取值含义见生命周期}） | 创建时间 |

**行生命周期**
…

### 关联表（他模块拥有，本模块仅引用）

| 表名 | 所属模块文档 | 本模块如何使用 |
|------|--------------|----------------|
| `pay_order`（支付订单） | [订单与支付.md](订单与支付.md) | {一句：本模块如何引用} |
```

### 字段与生命周期原则

- **表字段**：横向表；第二行写清该**表字段**在业务里表示什么，不只翻译列名（本章已处于某表语境，格内不必重复标「表字段」）。
- **数据流中的表字段 vs 参数**：见可读性规范 §「表字段与参数」。
- **术语**：英文枚举、缩写首次出现加括号注释（见可读性规范）。
