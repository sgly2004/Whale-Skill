# 前端交互规格文档模板

## 文件头

```markdown
# {产品名} 前端交互规格 — {视角或模块}

> 视角：用户 / 管理后台 / ……
> 关联 product 域：…
> 核对日期：（实现对照时填写）

**相关代码**
- `{pages/.../}` — 页面四件套
- `{components/.../}` — 子组件
- `{api/.../}` — 接口封装
```

---

## 文档层级

```
角色视角（小程序多端）或 后台角色
  └── 模块（服务 / 资源 / 论坛 / 个人 / 基地 …）
        └── 页面或交互单元（含弹层、抽屉、聊天卡片）
```

多角色产品：先按视角拆模块；与基准视角相同的条目写 **同 {基准}**，只列差异。

## 单条规格模板（页面 / 交互单元）

每个**页面或交互单元**（独立页、Tab 子页、抽屉、半屏弹窗、聊天卡片均算一条）使用同一模板：

```markdown
### {模块}-{子功能名}

**页面编码：** `/pages/xxx/index` 或 _（无）_

**挂载位置：** {父页面或 Tab} → {触发方式，如点击「去报名」、快捷卡片「意见反馈」}
（独立页可写「—」）

**结构 / 组件：**
- 容器类型：TabBar 页 | 普通页 | Tab 子页 | 抽屉 | 半屏弹窗 | 全屏弹窗 | 聊天卡片 | 列表 | 表单
- 区块划分：{如：顶部信息区 | 列表 | 底部固定按钮}
- 组件名（可选）：{如 ApplyIdentityCard、BillsPanel}

**页面功能（设计逻辑）：**
- 入口：从哪进入
- 主流程：用户完成目标的步骤（文字描述，禁止只写路由名）
- 门禁：实名 / 角色 / 会员 / 次数限制（如 1 天 1 次反馈）
- 状态与跳转：按钮状态枚举、点击后打开哪一页或哪一弹层
- 异常 / 空态：超限文案、未实名拦截等

**内容：**
- {区块名}
  - 展示：列表项 / 卡片上显示哪些字段
  - 表单字段：名称、类型、必填/选填、默认值来源（如从个人信息自动获取）、约束（最多 9 张图）
  - 操作：按钮文案、勾选协议名称
- {下一区块} …

**同 {基准视角} 差异：** （可选，仅列与基准不同的项）
```

## 实现核对块（代码对照时追加）

文档定稿或发版前，在每条规格下追加：

```markdown
#### 实现核对（YYYY-MM-DD）

**前端文件**
- `{path}` …

**未实现 / 不一致**
- …

**字段核对 — {子功能}**（表单类条目用表格）

| 规格字段 | 状态 | 说明 |
|---------|------|------|
| … | ✅ / ⚠️ / ❌ | … |
```

核对方法：

1. **页面编码** → 定位 pages 四件套（小程序）或 views 入口（admin）
2. **结构 / 组件** → 定位 components、popup、drawer
3. **内容** → 逐字段对照 wxml / 表单 schema
4. **页面功能** → 对照 ts 门禁、跳转、状态机

## 写法要点

**好的「页面功能」**（用户可感知）：

> 用户点击「快速匹配搭子」后，若当日免费次数未用尽则展示 3 个推荐搭子（头像、昵称、行业）；若已用尽则提示「明天继续」。需实名认证后生效，未实名时点击应拦截并引导实名。

**坏的「页面功能」**（禁止）：

> `navigateTo /pages/opc-match` → 调 `GET /match/recommend`

**挂载位置必须写清的情况**

页面编码为 _（无）_ 时，必须写明弹层/抽屉挂在哪、与规格是否要求独立页（避免实现成 popup 而规格要求独立页）。

## 范例摘录（OPC · 服务 · 首页）

```markdown
### 服务

**页面编码：** `/pages/home/index`

**挂载位置：** TabBar「服务」

**结构 / 组件：**
- 容器类型：TabBar 页
- 区块：聊天主区 | 顶部快捷卡片 | 历史记录入口
- 子容器：聊天卡片 ApplyIdentityCard（共建方/服务站申请）、FeedbackCard、OpcMatchCard

**页面功能（设计逻辑）：**
- 入口：默认 Tab 首页
- 主流程：文字交互获得智能体反馈；快捷卡片触发入驻/反馈/匹配
- 门禁：快捷卡片需实名；匹配展示当日剩余免费次数（普通 1 次/天，会员 10 次/天）
- 状态与跳转：意见反馈 1 天 1 次；匹配超限提示「明天继续」

**内容：**
- 如何成为共建方（ApplyIdentityCard 表单）
  - 姓名+电话（从个人信息自动获取）
  - 资源说明、主体信息（公司名、税号、开户行、对公账户）
  - 营业执照（图片，1 张）
  - 勾选《入驻合作协议》
- …
```

前端梳理时发现接口/状态缺口，应在规格中标注 **待后端确认**，并在 `doc/logic-design/backend/{module-slug}.md` 中补数据流。
